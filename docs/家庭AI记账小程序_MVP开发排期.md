# 家庭 AI 记账微信小程序——MVP 开发排期

## 1. 排期说明

本排期以现有产品、数据模型和 AI 技术架构文档为依据，以 Python Excel 账单分析原型已验证为起点，目标是交付一个可邀请家庭成员使用、可导入账单、可确认入账并查看统计的 MVP。

### 默认资源假设

- 周期：10 个工作周（每周 5 个工作日）。
- 后端：1 人，负责 FastAPI、数据库、导入和账务服务。
- 前端：1 人，负责微信小程序页面和交互。
- 算法/AI：0.5 人，可由后端兼任，负责规则、OCR 和 LLM 接入。
- 产品/测试：0.5 人，负责样例账单、验收和回归。
- 如果只有 1 名开发者，预计周期增加到 16～18 周；如果增加独立测试和算法开发，可并行压缩到 8～9 周。

### 交付原则

1. 先保证交易数据正确，再扩展 AI 能力。
2. 所有导入数据先进入中间层，用户确认后才正式入账。
3. AI 只负责解析和建议，不能绕过确认直接写入账本。
4. 每个阶段结束都要有可运行版本和可回归样例数据。

## 4. 功能点与依赖关系

```text
微信登录
   ↓
家庭 / 成员 / 权限
   ↓
账户 / 分类
   ↓
统一 Transaction Schema
   ↓
手动记账 ───────────────┐
                        ↓
文件解析 → 导入中间层 → 去重/转账/退款 → 分类 → 用户确认 → 正式入账
                        ↓
                   统计 / 预算 / 首页
                        ↓
              自然语言 / OCR / 个性化 AI
```

关键依赖：

- 没有统一交易模型，不开始多来源解析和 AI 接口开发。
- 没有家庭与账户权限，不开放交易和导入接口。
- 没有导入中间层，不允许导入数据直接写入正式交易表。
- 没有去重和转账识别，不把导入统计作为产品指标。
- 没有用户确认状态，不自动接受低置信度 AI 结果。

## 6. 测试与质量门禁

每个合并请求至少通过以下检查：

- 单元测试：金额解析、日期解析、列名映射、去重指纹、分类规则、统计聚合。
- 集成测试：登录、家庭权限、导入任务状态、确认入账和幂等性。
- 样例回归：支付宝/微信/银行卡真实脱敏账单各至少 1 份。
- 安全测试：越权访问、非法文件、超大文件、日志敏感信息和临时 URL。
- 数据对账：原始行数、重复数、正式入账数和收入/支出合计可解释。

质量门禁：阻断级问题未关闭，不进入下一里程碑；统计金额不一致、越权和重复入账属于阻断级问题。

## 7. 风险与缓冲安排

| 风险 | 影响 | 应对方案 |
| --- | --- | --- |
| 银行账单格式差异大 | 第 8 周延期 | 先锁定两种样例，解析器采用适配器模式 |
| Excel/PDF 引擎或编码问题 | 导入失败 | 预检文件、明确依赖、保留原始文件和错误行 |
| 去重误判 | 账务不可信 | 精确匹配自动处理，模糊匹配只进入人工确认 |
| 转账/退款匹配不准 | 统计失真 | 独立状态和关联关系，提供手动修正 |
| LLM 响应不稳定或费用高 | AI 体验受影响 | 本地规则优先，Schema 校验、超时、重试和限流 |
| 敏感数据泄露 | 合规和信任风险 | 数据最小化、脱敏、加密、临时文件过期和权限审计 |
| 小程序审核或第三方服务不可用 | 上线延期 | AI/OCR 设计为可选能力，核心手动和文件导入可独立运行 |

建议预留第 10 周 2～3 个工作日作为发布缓冲，不用来增加新功能，只处理阻断问题和试运行反馈。

## 8. MVP 后续排期

MVP 试运行稳定、导入率和分类准确率达到目标后，再安排：

1. 家庭资产负债：现金、银行卡、支付宝、微信、基金、股票、房产、车辆以及信用卡、房贷、车贷和借款。
2. 智能预算：根据家庭收入、固定支出和历史消费自动建议预算。
3. AI 财务分析：近三个月趋势、异常消费、预算超支预测和解释。
4. 轻量分类模型：使用用户确认数据降低 LLM 调用比例。
5. 在平台开放能力和合规评估通过后，再研究金融账户实时连接。

股票行情、理财推荐、投资建议、贷款、信用评分和复杂社交功能不进入本排期。
