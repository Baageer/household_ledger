# 家庭 AI 记账微信小程序——前端页面开发排期

## 1. 当前实现概况

前端代码位于 `wx_mini-program/miniprogram`，可使用微信开发者工具打开 `wx_mini-program` 目录。本版本范围为家庭、账户、账本、统计和账单导入，不包含 AI 入口及 AI 记账功能；AI 相关页面和接口统一安排到下一版本。后端 API 地址仍为示例地址，页面尚未连接可部署的 FastAPI 服务。

| 模块 | 当前状态 | 已实现内容 | 主要缺口 |
| --- | --- | --- | --- |
| 应用壳 | 已完成 | `app.js`、`app.json`、全局样式、TabBar、15 个页面路由 | 主题细节、分包和正式环境配置 |
| 登录与家庭 | 基础完成 | 微信 `wx.login` 调用、登录态缓存、家庭列表和创建入口 | 真实 `code2Session`、登录失效续期、家庭切换 API |
| 首页 | 基础完成 | 收支卡片、分类排行、预算进度、快捷记账 | 真机适配、空态/错误态精细化、真实接口联调 |
| 账单 | 基础完成 | 月份选择、日期分组、分页、下拉刷新、交易详情入口 | 筛选项、删除确认、加载性能和真实 API |

## 2. 前端目录与职责

```text
wx_mini-program/
├── project.config.json
├── miniprogram/
│   ├── app.js / app.json / app.wxss
│   ├── pages/          # 页面路由和页面交互
│   ├── components/     # 可复用展示和表单组件
│   ├── services/       # API、登录、交易、统计请求
│   ├── store/          # token、用户、家庭和当前家庭
│   └── utils/          # 金额、日期和表单工具
└── server/             # Python 领域服务，不属于小程序页面代码
```

公共请求必须自动携带 `Authorization` 和 `X-Family-Id`。页面只负责展示和交互，金额汇总、权限校验和正式入账均由服务端负责。

## 3. 开发排期

按 1 名前端开发、后端接口同步推进估算；若后端 API 和设计稿已准备好，可并行压缩周期。

### 阶段一：工程联调与基础体验（第 1 周）

| 任务 | 交付物 | 验收标准 |
| --- | --- | --- |
| 环境配置 | `apiBaseUrl`、开发/测试环境配置 | 真机请求可访问测试 API，域名校验策略明确 |
| 登录态 | 登录、401 清理、重新登录、家庭上下文 | 首次登录进入家庭选择，已有家庭进入首页 |
| 公共组件 | 空态、错误重试、加载态、金额/日期格式化 | 所有核心页面状态表现一致 |
| 视觉基线 | 色彩、间距、字体、按钮和安全区规范 | iPhone 常用窄屏无横向溢出 |

阶段一实现进度：环境配置、启动路由守卫、统一状态组件和 FastAPI 最小联调服务已完成；真实微信 AppID、合法域名、真机请求和生产 API 配置仍待联调验收。

### 阶段二：M1 家庭与账户页面（第 2 周）

| 任务 | 交付页面/组件 | 验收标准 |
| --- | --- | --- |
| 家庭切换 | `family/select`、`family-switcher` | 切换后所有请求使用新的 `currentFamilyId` |
| 成员管理 | `family/members`、邀请弹窗 | owner/admin 可邀请；成员可接受；普通成员不可管理 |
| 账户管理 | `accounts/index`、账户编辑表单 | 支持六类账户、公共账户、owner 绑定和停用 |
| 权限展示 | `permission.js` 和按钮状态 | 前端隐藏非授权操作，服务端 403 有统一提示 |

### 阶段三：M2/M3 账本与统计页面（第 3～4 周）

| 任务 | 交付页面/组件 | 验收标准 |
| --- | --- | --- |
| 手动记账 | `transactions/edit`、分类/账户/成员选择器 | 收入、支出、转账保存正确；保存期间不能重复提交 |
| 账单详情 | `transactions/index/detail` | 月份筛选、日期分组、分页和软删除与服务端一致 |
| 分类预算 | `categories/index`、`budgets/index`、`budget-card` | 分类引用保护、预算使用率和超预算状态正确 |
| 统计图表 | `statistics/index`、趋势图组件 | 日/周/月切换，分类占比总和与明细一致 |
| 首页完善 | `home/index` | 收支卡片、排行、预算和快捷入口在一次请求后正确渲染 |

### 阶段四：M4 账单导入（第 5～6 周）

| 任务 | 交付页面/组件 | 验收标准 |
| --- | --- | --- |
| 文件导入 | `imports/index`、上传进度组件 | 仅允许支付宝/微信支持格式，显示上传和解析状态 |
| 导入审核 | `imports/review`、审核行组件 | 错误、重复、低置信度行可区分和编辑；全部确认幂等 |
| 全链路回归 | 登录→家庭→记账→导入→统计 | 关键路径可在真机完成，失败可重试且不丢输入 |

阶段四实现进度：导入服务、文件内容上传、CSV/Excel 解析、重复/错误识别、审核编辑、失败重试和幂等确认已完成；真机文件选择兼容性、生产对象存储和异步解析任务仍待部署环境验收。

### 下一版本：AI 入口与 AI 记账（本版本不开发）

AI 入口、AI 记账页面、AI/OCR 解析和相关接口不纳入当前版本交付，待下一版本单独排期。下一版本计划包含：

| 计划任务 | 交付页面/组件 | 预期验收标准 |
| --- | --- | --- |
| AI 入口 | 首页/记账页 AI 入口 | 入口权限、引导和不可用状态明确 |
| AI 记账 | `ai/parse`、确认卡片 | AI 结果可编辑，用户确认后才创建正式交易 |
| AI 服务联调 | `services/ai.js` | `POST /ai/parse-text`、`POST /ai/classify` 可重试并处理错误 |
| AI 安全回归 | AI 结果和敏感信息展示 | 未经用户编辑确认不得入账，保留操作记录 |

## 6. 当前阻塞与依赖

1. `app.js` 的 `apiBaseUrl` 仍为 `https://api.example.com`，需要可访问的 FastAPI 环境才能联调。
2. `server` 当前为进程内领域服务，没有 REST 路由和持久化数据库。
3. 微信登录需要真实小程序 AppID、合法域名和 `code2Session` 配置。
4. 管理和导入页面依赖后端 API Schema 稳定后再进行完整交互开发。
5. AI 入口、AI 记账及相关 API 不在本版本范围，下一版本再进行 Schema 评审和联调。
6. 真机验收需要准备测试家庭、账户、分类、预算和支付宝/微信样例文件。
